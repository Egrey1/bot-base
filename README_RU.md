# База для Discord-бота — Технический обзор

В этом репозитории находится мой стандартизированный шаблон для ботов на **disnake**. Главная цель этой структуры — максимально переиспользовать код и свести к минимуму шаблонную рутину при старте нового проекта.

## 📂 Структура директорий

### `classes/`
Здесь хранится основная логика и абстракции.
*   `objects/` — модели данных и DTO (объекты передачи данных).
*   `handlers.py` — кастомные обработчики событий и вспомогательные функции (сюда же можно отнести систему СУП).

### `cogs/`
Модули с командами. Это самая важная часть архитектуры.
*   **Группировка:** Команды разбиты по функциональным группам (например, `mod_command`, `economy`).
*   **Реализация:** Внутри каждой группы есть папка `commands/`. Именно там лежат файлы с отдельными командами (например, `kick.py`, `ban.py`).
*   **Сборка (Assembly):** Файл `__init__.py` внутри группы работает как сборочный модуль. Он импортирует все команды из папки `commands/` и определяет родительский класс, который от них наследуется.

    **Пример (`cogs/mod_command/__init__.py`):**
    ```python
    from .commands import * 

    # Наследует поведение от импортированных команд
    class ModCommand(Kick): 
        pass

    def setup(bot):
        bot.add_cog(ModCommand())
    ```
*   **Автоматическая загрузка:** Основной загрузчик в `main.py` (или вспомогательный код в `cogs/__init__.py`) проходит по этим группам и автоматически вызывает их функции `setup()`. Тебе не нужно вручную прописывать каждый ког в главном файле.

### `data/`
Слой доступа к данным.
*   `dbConnect.py` — отвечает за подключение к базе данных и операции CRUD (создание, чтение, обновление, удаление). Здесь хранится вся логика работы с `.db` или `.json` файлами, чтобы не засорять ею коги.

### `dependencies/`
Глобальные общие ресурсы.
*   `main_deps.py` — здесь хранятся глобальные константы, общие объекты конфигурации и псевдонимы типов. Это единый источник истины для переменных, которые нужны во всём проекте.

### `config.py`
Точка инициализации конфигурации.
*   Инициализирует зависимости из папки `dependencies`.
*   Загружает секретные данные из файла `.env` (например, `TOKEN`).

### `main.py`
Точка входа в приложение.
*   Импортирует `config` и `dependencies`.
*   Запускает экземпляр бота.

---

## ⚙️ Как это работает (алгоритм запуска)

1.  **Старт:** Запускается `main.py`, который подтягивает глобальную конфигурацию и зависимости.
2.  **Загрузка когов:** Система сканирует папку `cogs/` в поисках папок, внутри которых есть функция `setup()`.
3.  **Разрешение команд:** Когда пользователь вызывает команду, бот находит её через собранный класс кога (например, `ModCommand`).
4.  **Доступ к данным:** Если кому-то из когов нужны данные из базы, он обращается к хелперам из папки `data/`.

---

## 🔐 Безопасность и лучшие практики

*   **Управление секретами:** Токены никогда не хранятся прямо в коде. Они загружаются из файла `.env` через `os.getenv` в файле `config.py`.
*   **Чистота Git:** Файл `.gitignore` настроен так, чтобы в репозиторий не попадали служебные файлы: `__pycache__`, `venv`, `.env`

## 📝 Примечания для разработчиков (как вносить изменения)

### Добавление новой команды
Если нужно добавить одну команду в существующую группу:
1.  Создай новый файл в папке `cogs/<группа>/commands/` (например, `cogs/mod_command/commands/mute.py`).
2.  Убедись, что `__init__.py` группы импортирует его (обычно это делается через `from .commands import *`).
3.  Никаких изменений в `main.py` не требуется — команда подхватится автоматически.

### Создание новой группы команд
Если нужно добавить целый новый модуль (например, экономику):
1.  Создай новую папку в `cogs/` (например, `cogs/economy`).
2.  Внутри создай подпапку `commands/` и файл `__init__.py`.
3.  В `__init__.py` пропиши функцию `setup(bot)` и базовый класс.
4.  Загрузчик увидит новую папку и подключит её сам.

## 📄 Требования и установка

Для работы проекта нужны следующие библиотеки:
*   `disnake`
*   `python-dotenv`

**Установка:**
```bash
pip install -r requirements.txt
```

**Настройка:**
1.  Создай файл `.env` в корне проекта.
2.  Добавь туда свой токен:
    ```env
    TOKEN=твой_токен_бота
    ```
3.  Убедись, что `.env` есть в `.gitignore`.

**Запуск:**
```bash
python main.py
```
